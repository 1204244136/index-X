# EPUB 命名规范（表头、文件名与图片资源）

文档职责与入口见 [文档索引](README.md)。

本文件是**命名与配对形态**的规范正文：中日 XHTML 靠什么确定稳定配对单元、中文文件名与包装后缀怎么取、图片资源如何带作品号。作品号体系与系列编号见 [AGENTS.md](../AGENTS.md)；行模板与结构规约见 [EPUB 结构规范](epub-structure-spec.md)；译名取舍见 [译名裁定总表](translation-name-rulings.md)。

## 一、XHTML 表头

- 「表头」是用于中日 XHTML 配对的稳定内容标识，必须区分于目录名、EPUB 页码和语言侧的描述后缀。
- 普通主系列表头为 `S<系列>_<卷序>-<内容序>`，例如 `S1_03-05`。
- 外典表头为 `S5_<合订卷>_<独立作品>-<内容序>`，例如 `S5_01_03-02`。工具不得只使用 `S\d+_\d+-\d+` 这类只能识别两段数字的正则。
- 日期短篇如果有编号章节，表头为 `S6_YY.MM.DD-<内容序>`，例如 `S6_24.06.07-02`。如果日文只有 `start.xhtml`、中文只有 `Main.xhtml` 等无共同表头文件，应先按相同的 `S6_YY.MM.DD` 作品号和语义内容确认关系，不得仅按文件名自动配对或虚构表头。确认对应关系后，日文单文件作品应重命名为与中文对应的表头文件名（如 `start.xhtml` → `S6_14.09.10-Main.xhtml`、`S6_18.04.10-Chapter.xhtml`），并同步更新 OPF/NCX/nav 引用。
- SP 等使用名称的内容以稳定名称作为表头，例如 `S1_25-Uiharu_Kazari`；这类文件不得强行归入数字章节正则。
- 表头之后的 `_p-004`、`_Chapter2`、`Chapter1`、`_Afterwords` 等是页码、章节语义或语言侧包装后缀，不属于表头。例如日文 `S5_01_03-02_p-021.xhtml` 与中文 `S5_01_03-02_Chapter2.xhtml` 的共同表头是 `S5_01_03-02`。
- 配对时必须先提取完整作品号，再提取内容序或稳定名称；不得把 `S5` 的独立作品号或 `S6` 的日期截断。
- 历史文件名可能不完全符合上述形式，例如日文 `S5_02-03_coldgame_p-020.xhtml` 对应作品号 `S5_02_03`。这类情况必须作为明确别名或人工映射处理，不得通过宽松模糊匹配猜测。

## 二、中文 XHTML 文件名与包装后缀

- 中文 XHTML 文件名优先表达两层信息：先用作品号或表头确定稳定配对单元，再用英文语义后缀说明该文件在中文 EPUB 中的作用。语义后缀用 ASCII 英文、数字和下划线保留现有大小写与拼写，不得为了格式化而批量改名。
- 带数字内容序的正文或正文附属文件使用 `<表头>_<语义后缀>.xhtml`。例如 `S1_01-02_Chapter1.xhtml`的表头是 `S1_01-02`，`Chapter1` 只说明中文章节语义。
- 内容序是文件在该作品中的对齐顺序，语义后缀中的章节数是展示语义，两者不要求相等。例如 `-02_Chapter1` 表示第 2 个对齐单元是第 1 章。配对和排序必须使用表头中的内容序，不得使用 `ChapterN` 反推顺序。
- 数字内容序始终从 `-01` 开始，`-00` 是非法内容序。需要参与中日对齐的导言、引子或序页占用 `-01`，其后的 Prologue、Chapter 等依次顺移；不得为特殊语义保留零号，也不得把既有 `-00` 当作包装页而跳过验证。
- 常见的编号内容语义后缀包括 `Before_the_Prologue`、`Prologue`、`ChapterN`、`Between_the_LinesN`、`Epilogue`、`After_the_Epilogue` 和 `Afterwords`。它们只描述内容类型；同一作品中的实际顺序仍由表头内容序决定。
- 「引子」与「尾声」是聚合文件，不得按量拆分或并入相邻章节文件：序章（`Prologue`）之前的内容无论多少只写为一个文件「引子」，语义后缀用 `Before_the_Prologue`；后记（`Afterwords`）之后的内容无论多少只写为一个文件「尾声」，语义后缀用 `After_the_Epilogue`。判定以表头内容序为准：引子位于第一个 `Prologue` 之前，尾声位于第一个 `Afterwords` 之后。
- 「尾声」只收**紧接后记的连续正文文本页**：后记之后一旦遇到非正文页（纯插图页、封底 `hyou4`、著者介绍/版权页），即从该页起进入**书末附录**，其后的页（包括紧跟的著者/插画师介绍页）一律不并入后记、不开「尾声」，保留原始文件名不重命名不合并。附录不是故事性尾声，不得因其含正文段落就给它内容序。
- 某些作品使用与正文标题对应的专用语义后缀，例如 `Sub.02`、`Period.07`、`Ingredients1`、`Bike_stunt1` 或 `A_Cardinal_Error.34`。这些后缀应按作品原有命名保留，不得为套用通用模板而改成 `ChapterN`。
- 无数字内容序的作品级文件使用 `<作品号>-<包装后缀>.xhtml`。常见包装后缀为 `Cover`、`Back_cover`、`Illustrations`、`Information`、`Introduction`、`Note` 和 `Special`。例如 `S1_01-Cover.xhtml` 与 `S1_01-Information.xhtml`。
- `nav.xhtml` 是 EPUB 导航文件，不使用作品号包装，不属于表头配对范围。
- 不能仅根据「作品号后直接使用连字符」就断定文件是包装页。SP 命名正文如 `S1_25-Uiharu_Kazari.xhtml` 以稳定名称参与配对；日期短篇也可使用 `S6_14.09.10-Main.xhtml`、`S6_10.06.26-Chapter.xhtml`、`S6_10.06.26-Prologue.xhtml`、`S6_10.06.26-Epilogue.xhtml` 或 `S6_10.06.26-Manga.xhtml` 承载实际内容。这些文件必须结合作品类型、导航顺序和内容语义判定。
- 同一语义词可能因位置不同而承担不同角色。例如 `S1_01-Introduction.xhtml` 是作品级无编号文件，`S5_01_01-01_Introduction.xhtml` 则是带表头、参与顺序对齐的内容文件。工具必须同时检查分隔符与是否存在内容序，不得只按后缀文本分类。
- 中文文件名中如果缺少规定分隔符，例如历史文件 `S5_01_03-01Chapter1.xhtml`，应视为待报告的命名异常；工具可以通过明确兼容规则识别，但不得将该异常扩大为默认命名方式。

## 三、图片文件名与资源引用

- 导入、重建或预处理 EPUB 时，图片资源文件名必须带完整作品号前缀，格式为 `<作品号>-<原稳定图片名>.<扩展名>`。例如 `i-030.jpg` → `S4_05-i-030.jpg`、`kuchie-001.jpg` → `S4_05-kuchie-001.jpg`、`cover.jpg` → `S4_05-cover.jpg`。
- 作品号之后保留源图片的稳定语义名、大小写、页码和扩展名；不得仅依据图片出现在哪个分页 XHTML 中猜测内容序，也不得把同一图片的多处引用误当成多个配对单元。经人工确认角色后，可以按既有档案约定命名为 `Cover`、`IllustrationsN`、`i-NNN` 等。
- 图片重命名后必须同步更新 XHTML、OPF、NCX、nav、CSS 和 SVG 中的引用。预处理与发布前验证必须阻断无作品号图片、悬空资源引用、XML 语法错误和不合法 EPUB 容器，不得只检查正文 XHTML 的标题槽位。

## 四、机器判定

命名与配对不靠人眼逐条比：机器判定实现在 `tools/`，入口、参数与失败边界见 [工具合同](../tools/README.md)。本文件只写形态规范，常量、正则与例外清单以工具实现为准，不在此复制；已确认的配对与模板例外只登记在 `tools/alignment_rules.py`，历史作品号别名只登记在 `tools/epub_ids.py`。
