# 校对复核共用工具与执行契约优化

文档职责与入口见 [文档索引](../README.md)。

## 范围与依据

本次维护针对 Antigravity 执行校对复核时，各切片重复创建读取、分页、装配和校验脚本的现象。初始观察批次为 S1_21，计划含 1214 个语义片段、11 个切片。输入已包含旧／新译、日文及邻接上下文，重复工作主要发生在消费输入和交付报告阶段；脚本文件数不代表执行次数，未据此估算节省比例。

修改仅涉及复核工具、测试、skill、复核契约和工具合同；没有执行 EPUB 内容回改或同步。保留既有全量逐 ID 查证、语义单元边界、Lead 独立证据验收及 R4 呼应复核职责。

## 修改事实

1. 新增一个共用命令入口 `tools/proofread_session.py`，提供 `init / prepare / read / context / assemble / validate / coverage`；底层分为 `proofread_packets.py` 与 `proofread_results.py`，原子新建报告由一个共享实现承担。
2. 将稳定 ID、精确归属核对、默认最小中日窗口、底字／注音两轨、来源摘要和输入预算集中处理。中文实际行必须与清单新译相符；配对行数异常报告双方行数及差值。跨物理行 ruby 暂不支持，明确阻断，避免悄然改变行号口径。
3. 决策草稿逐项显式填写，不用默认保留或通用理由填补缺项。正式报告统一装配，验收实际比较所引日文及注音。覆盖从显式有效结果选择派生，缺失或不合格切片整片归未覆盖，待人工与未覆盖阻断完成。
4. 统一子智能体写入边界：直接填写本片决策数据，调用共用读取、装配与验收入口。Lead 按具体依赖添加有封存摘要的条目专属上下文补包；输入源和归属保持冻结。
5. 将纯格式修订与证据／语义重审分开：同 attempt 的 `.rN` 比较完整前驱链，不能借修订改变判定、理由、引用或发现项；真正取证失败沿原边界重发。R7 前保存已验收覆盖快照，回改另建验收轮，最终报告分别保留原轮和验收轮证据。
6. 初始 `proofread_review.py` 的 TSV 改用标准 CSV 字段引用，保留双引号、制表符及多行内容，避免后续按标准 TSV 读取时丢失原始字段。
