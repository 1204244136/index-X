## 结论一：纵中横（tcy）规则次序导致两位数小节未转 h2

- 现象：S1_10、S1_13~S1_17、S1_19~S1_22、S2_23 等约 20 个大章「中文比日文多 h2、多 2 行/处」。
- 根因：BW 竖排版两位数小节号源码为 `<p>　　　　<span class="tcy">10</span></p>`，
  「纵中横 span 解包」排在「裸数字小节转为 h2」之后，纯数字正则匹配落空，
  留下 `<br/><p>10</p><br/>` 三行噪声。
- 修复：解包规则前置到规则集第 3 位；「裸数字小节转为 h2」行尾补 `\r?` 锚定。
- 全量重跑后该批差异全部自动对齐。

## 结论三：S6_22.06.10 章名图片扉页根因与脚本修复

- 现象：日文 `-01` 为 2937 行（序章～终章 16 页全并入），`-02` 实为后记；
  中文侧正确分为 `-01`~`-07` 七个文件。
- 根因（两层）：
  1. `pairing_header_renames` 内容序只认「L4 文本 h1」；本书章名均为整页 SVG
     扉页（`<div class="main" id="toc-NNN">` + m-001~m-006.jpg），扉页作为非正文页
     沿用当前序，全书正文无 h1 可切分。
  2. `bw_page_header_overrides.json` 已有该书完整审计映射，但程序化调用
     `process_epub` 未传 `page_map` 时映射不生效（仅 CLI main() 自动加载）。
- 修复：
  - `bw_preprocess.is_image_title_page()`：非正文页 + main 带导航锚点 id = 章节边界，
    内容序递增（排在后记/附录闩锁之后）；普通插图（main 无 id）不受影响。
  - `merge_bw_pages.parse_page_content` 提取 `main_id`；`group_units` 对无表头输入
    按扉页 id 切分新单元（带表头输入仍以内容序优先，不与显式映射冲突）。
  - 扉页单元的章名（h1）由 `attach_nav_titles` 从原版导航精确补回。
- 验证：显式映射与自动推导两条路径表头序列一致；重新生成后 7 个文件行数
  （45/353/442/513/1519/86/30）、图片行、h2 位置与中文侧逐项一致，XML 全部合法。
