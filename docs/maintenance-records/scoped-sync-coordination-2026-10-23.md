# 局部同步与共享工作区协调修复（2026-10-23）

文档职责与入口见 [文档索引](../README.md)。本记录承载 `035b4d3d` 后续工具审计的修复事实和验证结果；当前操作合同见 [工具说明](../../tools/README.md)，协作边界见 [AGENTS.md](../../AGENTS.md)。

## 范围与原因

- 多个对话可能共用工作区；按书发布必须保留范围外内容及已发布基线，同书内容是否完成仍需任务间协调。
- 原 B/C 入口各自读旧清单后全量回写：即使两个进程选不同书，后完成者也会覆盖先完成者的基线。限定范围的 `--force` 另会清空其它书的记录。
- 原拉取入口替换缓存前不检查未发布变化，直接拉取可能丢失所选书的本地有效内容；精确书籍列表也无法传给 A。
- 原配对规范化没有作品／文件筛选，单书根返回成功但处理零文件；此项已由 `cee8dd4e` 单独修复。
- 原提交的留档漏记 `--only-books` 并有一处新文示例笔误，已由 `178696c5` 单独勘误。

## 修复

1. 统一发布、B/C、拉取和清单入口对同一缓存的完整读写事务实行互斥。Python 和 PowerShell 参与者各自持有系统锁；父进程退出后，仍在工作的子进程继续保持保护。失活成员在后续登记时清理，预览不创建锁文件。
2. B/C 只更新成功且选中的书；强制重做保留范围外的基线。首次按书建清单仅登记指定范围，空 `--update-books` 明确拒绝。
3. 拉取支持 `-OnlyBooks`，A 直接传递统一入口的精确范围。待拉取书先整批检查缓存变化，`-SyncToEpub` 同时检查归档；未包含在外部包中的本地变化会阻断，已包含的相同变化允许继续。`-Force` 保留该保护，范围外书目录不清理。
4. 命令合同与业务 skill 的写入／同步示例改用任务范围。AGENTS 补充跨对话同文件写入交接、同书完成状态及同步锁边界；Git 既有其它任务暂存时的提交分支统一在提交规范维护。
