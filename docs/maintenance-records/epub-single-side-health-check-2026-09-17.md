# EPUB 单侧体检口径与基线（2026-09-17）

## 范围与结论

- 范围：版本化 `EPUB/` 下全部 78 本书、1197 个 XHTML（不含 78 个 `nav.xhtml`）。
- 目的：把「**不需要中日对照就能判定**」的结构问题收敛到一条可复跑的只读命令，作为每日
  字符级规范化之外的第二道检查闸；同时把「哪些东西刻意不检查」写死，避免后人反复试错。
- 结论：11 个检查项在全库上命中 **0**（error 0 / warning 0）。唯一非零项是 `template`
  的 39 处，全部落在 3 本已裁定不纳入正文模板检查的文件上，走显式豁免。
- 本记录冻结的是**判定口径与基线**，不是某个时点的报告。工具行为见 `tools/README.md`
  「EPUB 单侧体检（只读）」。

## 单侧检查的能力上限

CI 只有中文 `EPUB/`，看不到 `.cache/` 里的日文侧，因此下面三类问题在 CI 里**结构上做不到**：

- 中日行错位、h2/图片行/`<br/>` 位置不一致；
- 加粗范围是否对应日文傍点（判定依据是日文侧 8397 个傍点段）；
- 注音义务（「日文有特殊注音则译文必须有注音」的锚点在日文源）。

单侧检查的上限就是「不需要对照就能判定的问题」。中日对照仍需本地定期跑
`tools/check_alignment.py`；不要因为 CI 绿了就认为对齐无问题。

## 检查项与基线

| 检查项 | 判定 | 基线 | 级别 |
| --- | --- | ---: | --- |
| `XML` | 每个 XHTML 能被 `xml.etree` 解析；`<img>` 都带 `src` | 0 | error |
| `template` | 固定行模板与正文行原子性（复用 `check_alignment.check_file`） | 0（+39 豁免） | error |
| `bold-punct` | `<b>` 段内含标点（复用 `text_norm.split_bold_punct`） | 0 | error |
| `bold-empty` | 空 `<b>` 段 | 0 | warning |
| `bold-pair` | `<b>` 开闭标签数量不一致 | 0 | error |
| `ruby` | `<ruby>` 缺 `<rt>` 注音 / 开闭不配对 | 0 | error |
| `seq-00` | 非法内容序 `-00` | 0 | error |
| `dup-header` | 同一本书内重复表头 | 0 | error |
| `seq-gap` | 同一作品内内容序缺号（只对含 ≥2 个内容序的作品判定） | 0 | warning |
| `img-prefix` | 图片文件名缺完整作品号前缀（全库 1055 张图片） | 0 | error |
| `dangling` | XHTML/OPF/CSS 引用的资源或锚点不存在 | 0 | error |

`bold-punct` 与每日规范化 CI **同源**（同一个 `split_bold_punct`），这是有意的：体检说
「有 N 处」时，CI 一定会去改同样这 N 处；两个工具的判定不会漂移。

## 刻意不纳入的检查项

判定不唯一或有系统性误报，纳进来只会制造噪声：

- **引号配对**。全库 21 处「开/闭不在同一段」的写法，三类原因都是刻意的：
  1. 引语跨段（`『` 在一段、`』` 在另一段）；
  2. 强调性收尾（`……仍可继续进行。』`，整段是文件摘录，收尾引号独立成段）；
  3. 把原文截断以模拟通讯中断（`「喂，我好歹还是知道要保留点警戒d`）——同一批段落里
     普遍存在 `${中文}d`、`${中文}xi` 形式的截断，是作者的演出手法，不是漏字。
  逐条都要判断该补还是该删，不满足「替换值唯一」，因此**不修也不进门禁**。
- **Note 列表项编号**。它与正文条目号是两套编号；且条目号与普通正文行（如
  「4.5 个榻榻米的大小」）在形式上无法区分，任何判据都会误报（试做时唯一命中就是这一条
  假阳性）。Note 编号一致性由 `check_note_order.py` 在缓存上按「定义顺序 vs 正文首次引用
  顺序」判定，口径更强，不重复实现。
- **换行符**。`AGENTS.md` 明确「换行符不作为修改对象」，`EPUB/` 出现 CRLF 属仓库容忍的
  既有态（8 个文件），不是问题。

## 豁免名单

`EXEMPT_BOOKS` 按「书 + 检查项」豁免，不是整本跳过。目前只有三本、只豁免 `template`，
且都不是「待修的问题书」而是**已裁定不纳入正文模板检查**的文件：

| 书 | 豁免项 | 依据 |
| --- | --- | --- |
| `S0_00` | `template` | 「读前必看」非正文作品，结构本身与正文模板无关（18 处） |
| `S6_10.06.26` | `template` | 无 BW 分页源，明确不处理（11 处） |
| `S6_24.12.10` | `template` | 无 BW 分页源，明确不处理（10 处） |

豁免外的模板命中为 0，因此这三本的既有结构差异不会淹没真信号（豁免不生效时它们会让
该项固定报 39）。往名单里加条目等于放宽体检口径，必须同时写明依据。

## 工具自身可信度

体检类工具最大的风险不是漏报，而是判定写错却**永远报 0** 却看上去一切正常
（正则静默失配、路径没匹配上、`--only` 分支写反）。因此 `tools/tests/test_check_epub_health.py`
对每个检查项都构造一个能触发它的最小反例，另用一份正常样本确认不误报，并单独验证：

- 解析失败时只报 `XML`、不向行级检查泄漏噪声；
- `bold-punct` 的三条保护片段（XML 实体 `&amp;`、作品号 `[S5_01_01]`、缩写点 `Mr.`／小数 `3.5`）
  确实不被拆开；
- 豁免按项生效（豁免 `template` 不影响同书其它检查项）；
- `--strict` 只在 error 级命中时非零退出。

首版实测：XML 项曾把 1197 个文件里的 1275 个当目标（把 `nav.xhtml` 算进来），
`img-prefix` 曾因测试夹具的作品号与图片前缀不一致而"通过"——两处都是靠这套负向自检发现的。

## 复现

```powershell
python -m unittest discover -s tools/tests -p "test_*.py" -v
python tools/check_epub_health.py --strict
```

基线复查（应全部为 0，`template` 显示 39 处已豁免）：

```powershell
python tools/check_epub_health.py --tsv .cache/epub-work/epub-health.tsv
```

`EPUB/` 单侧体检只读：不写 `EPUB/`、不写 `.cache/`（除显式 `--tsv/--json` 指定路径），
不提交、不发版。CI 侧为 `.github/workflows/check-epub-health.yml`（每日 06:00 UTC+8，
排在每日规范化之后），`permissions` 只有 `contents: read`。
