# 中日 XHTML 行对齐格式规范

## 目标

对表头形如 `S1_01-01` 的中日对应 XHTML 生成规范化缓存，使相同逻辑内容尽量位于相同行号。规范化只作用于 `.cache/`，不直接改写原始 EPUB 或 `EPUB/` 发布源文件。

## 匹配边界

- 仅比较中日两侧表头完全相同且各自唯一的文件。
- `nav.xhtml`、封面、版权页和没有表头的图片页不参与常规行对齐。
- 图片页、空壳页与正文页的合并必须先确认归属，再进入规范化流程。

## 固定外层结构

中日缓存统一使用三行文件头和一行文件尾：

```html
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml"><head>...</head><body><div class="main">
```

文件最后一行固定为：

```html
</div></body></html>
```

外层标签不得与标题、正文、图片、署名等有意义内容处于同一物理行。

## 内容行规则

正文区域按“一个语义块一行”组织：

1. 每个 `h1`、`h2` 或其他章节标题独占一行。
2. 每个正文 `p` 独占一行；`ruby`、`rt`、`b`、`span`、注释链接等内联标签不得在内部换行。
3. 图片或 SVG 独占一行。图片外层的纯布局 `p`、`div` 可以保留，但整块必须在同一行。
4. 署名、引文来源、日期和右对齐说明各自独占一行，并直接跟随所属正文，不额外插入 `<br/>`。
5. 禁止纯空白物理行。
6. 有意义的内容行不得包含 `</body>`、`</html>` 或主容器的结束标签。

## 换行标签规则

- 每个视觉间隔写成一行 `<br/>`。
- 连续多个换行必须按实际数量逐行书写，例如三个换行必须写成：

```html
<br/>
<br/>
<br/>
```

- 禁止在同一物理行中放置多个 `<br/>`。
- 中日两侧同一位置都有视觉间隔时，换行数量必须一致；数量不同则根据原文结构和上下文确认正确数量，再在缺少的一侧补齐或从多余的一侧删除。
- 只有一侧存在的 `<br/>` 默认视为待检查项；确认属于排版噪声时删除，确认具有章节分隔意义时给另一侧补齐相同数量的换行行。
- 不允许使用纯空行代替 `<br/>`。

### 标题页例外

标题块（`h1`/`h2` 内的 `span`、标题文字和其排版用 `<br/>`）视为一个整体。标题块内部允许 `<br/>` 与标题文本或 `span` 保持同一物理行，不强制把 `<br/>` 拆成独立行。例如：

```html
<span>序　章<br/></span><span class="font08">幻想杀手少年的故事</span>
```

该例外仅适用于标题块，不适用于正文、署名、引文来源或普通图片说明。

### 图片换行例外

图片或 SVG 本身作为一个内容块独占一行。若中日任一侧在图片块正上方和正下方存在仅用于图片排版的 `<br/>` 行，则这些相邻换行行不计入对齐，规范化时删除；图片行本身保留。只有图片前后确实属于正文段落分隔、且另一侧也存在对应语义分隔时，才保留相应 `<br/>`。

## 布局标签规则

- `div`、`span` 等纯布局标签不单独占行，应并入其所属语义块。
- 多层右对齐容器统一压缩在署名或引文来源所在行。
- 文件尾所有剩余布局容器由固定文件尾统一关闭。
- 标题区的 `start-3em`、`font-*` 等样式差异可以保留，但不得增加物理行。

## 后记专门规则

后记通过文件名中的 `Afterwords`、标题文本“あとがき/后记”或表头对应的导航语义识别。识别为后记后，正文与作者署名按以下关系处理：

1. 后记最后一条有意义的正文与作者名是两个连续的语义块，各自独占一行。
2. 正文与作者之间不插入 `<br/>`，也不保留纯空行；作者应直接跟随最后一条正文。
3. 日文署名统一保留在一个署名容器行中，例如：

   ```html
   <div class="align-end"><p>鎌池和馬</p></div>
   ```

   中文署名统一为一个右对齐段落行，例如：

   ```html
   <p class="right">镰池和马</p>
   ```

4. 署名容器的内部标签不得跨行；主容器、`body`、`html` 结束标签不得与正文或作者名同一行。
5. 后记中出现“作者名 + 作品名/来源说明”的组合时，作者名和来源说明分别占行；不能把来源说明误并入作者行。
6. 存在多个作者、译者、绘者或引用来源时，按原文顺序逐项排列，每个署名或来源各占一行，不额外插入空行。
7. 后记没有明确作者署名时，不得为了对齐虚构作者行；只规范现有正文、图片、引用和结束标签。
8. 图片后记、空壳后记和正文缺失的后记不套用本节的行数补齐规则，应单独标记处理。

## 对齐处理顺序

1. 解析 XHTML，禁止使用正则表达式直接拆分 XML 标签。
2. 提取固定外层结构、标题、段落、换行组、图片、SVG、署名和引文来源等语义块。
3. 将每个语义块序列化为单行，清除标签内部的意外物理换行。
4. 将非标题块中同一物理行的多个 `<br/>` 拆分，使每行只包含一个 `<br/>`；标题块按“标题页例外”保留内部排版换行。
5. 对照中日上下文统一相同位置的 `<br/>` 数量，并删除纯空行和确认无意义的单侧换行。
6. 对中日语义块序列进行顺序比较。
7. 仅自动处理外层标签、布局容器、换行组和图片包装差异；正文段落数量不同则输出人工检查项。
8. 使用固定文件头和文件尾重新序列化缓存文件。

## 不自动处理

- 一侧缺失实际正文段落。
- 一侧把多个正文段落合并为一个段落，或把一个段落拆成多个段落。
- 图片内容或图片归属章节不同。
- 只有图片、没有正文的表头文件。
- 翻译增补、删节、脚注正文或引文内容差异。

这些情况必须进入人工检查报告，不得仅为凑齐行数而插入空行。

## 验收条件

- 中日对应文件的固定文件头均为 3 行，固定文件尾均为 1 行。
- 文件中不存在纯空白行。
- 内联标签内部不存在物理换行。
- 有意义的内容行不包含文件尾标签。
- 每个 `<br/>` 独占一个物理行，同一行不得出现多个 `<br/>`。
- 中日对应位置的 `<br/>` 数量一致。
- 自动处理后行数仍不相同的文件全部列入人工检查清单。
- 随机抽查相同行号时，中日内容应属于同一标题、段落、图片或署名位置。
