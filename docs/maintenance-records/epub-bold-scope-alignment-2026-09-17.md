# EPUB 加粗范围与原文傍点对齐（2026-09-17）

## 背景与规范依据

`docs/translation-spec.md` 一.8：原文右侧傍点（着重号）在成品里表现为**加粗**；加粗是排版转换结果，不是语气强调的增译。原文傍点对应的文字没有加粗、**加粗落在标点上**、加粗范围与傍点明显不符 → 缺陷。

本轮处理的是后两类之外的两件事：**加粗范围与傍点不符**（含漏加粗、凭空加粗、落在错行）与**加粗内含标点**。

判定口径有两条，都不依赖主观：

1. **加粗对齐的是语义范围，不是逐字**。一句情感强烈的话若原文整句傍点，中文也整句加粗，**包含中文的增译**；不因中日段数对不上而把增译晾在加粗之外。
2. **标点不得进入加粗**。标准**从日文傍点自身的字符构成反推**，而非人工指定。

## 顺带修复：BW 预处理漏转组合 class（提交 `e81f01e3`）

排查 `S4_02-06:731` 时发现日文源残留 `<span class="bold em-sesame">`。三层比对（BW 提取源 → `日文原文` epub → `.cache`）确认：**`.cache` 与源逐字节一致**，问题出在预处理规则——`tools/bw_extract_preprocess.json` 的「着重号span转b标签」按整串精确匹配 `<span class="em-sesame">`，漏掉 `bold em-sesame`、`tcy bold` 等组合 class。

修法（规则 v7）：加粗/着重号 span 转为按 **class token** 匹配（前瞻 `(?=[^"]*\bbold\b)` / `(?=[^"]*\bem-sesame\b)`），纯 `tcy` 仍走解包规则。全库 87 本日文 epub 中仅 `S4_02` 命中（3 个 span，同在 L731 的拟声词），已用新规则重建该卷日文源并重新解包缓存：重建产物与旧源逐字节对比**仅该行不同**、59 个 epub 条目完全对应、行数 1171 不变、`check_alignment.py` 仍 0 问题。修复后全库残留 span 傍点 3 → 0，日文 `<b>` 总数 8394 → 8397。
