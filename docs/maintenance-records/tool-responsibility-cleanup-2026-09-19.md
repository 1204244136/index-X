# 工具职责检查与精简（2026-09-19）

## 检查口径

结合工具目录、README、CodeGraph 调用关系和现有测试，重点核查发布、规范化、检查、字数统计与校对复核工具。以“同一规则是否多处实现、共享能力是否寄居于不相关入口”为精简依据；命令数量和文件长度不单独构成删除或拆分理由。

## 结论与处理

| 范围 | 结论 | 处理 |
| --- | --- | --- |
| 发布 A/B/C 与统一入口 | 不同方向的执行顺序和冲突约束有独立意义，但上传及拉取状态解析重复，统一入口借用反向发布内部能力 | 保留入口；`scan_epub` 归入 `manifest.py`，`find_conflicts`、`read_pull_state` 归入 `sync_core.py`；两个发布方向共用 `upload_book`，状态更新共用解析器 |
| 单文件/配对规范化 | 已共用 `xhtml_template.py`；区别是文件选择和配对成功条件 | 保留两个编排入口 |
| BW 预处理/分页合并 | 分别处理源分页结构和章节跨页衔接，输入阶段不同 | 保留；修正 README 中旧的换页 div 说明 |
| 对齐/翻译规范/译注顺序/单侧体检 | 检查对象与判定条件不同，共享模板等规则属于正常复用 | 保留独立检查入口，不合成万能修复器 |
| 字数统计/成分页数估算 | 后者复用字数分析并增加印刷页锚点推算，输出含义不同 | 保留两个入口 |
| `epub_audit.py` | 名称看似通用，实际只扫描硬编码的“風力発電/风力发电”；另被复核与查证脚本当作文本库导入 | 删除一次性入口；原有 `text_of` 原样语义迁至 `xhtml_text.py`，迁移两个调用方和当前说明中的引用 |

`xhtml_text.text_of` 仍保留注音，保证注音修订不会从复核 diff 中消失；原文查证仍先删除 rt/rp 再提取文本。字数统计使用的去注音、去空白口径不同，不强行合并。

上传仍遵循原有方向顺序。上传或写拉取状态出现 `OSError` 时，发布入口返回失败，成功书籍清单不会推进；反向发布不会继续覆盖缓存。此处未引入事务回滚，上传成功但状态写入失败时，外部副本仍可能已更新，需要后续按既有冲突流程处理。

删除的旧脚本可从 Git 历史恢复；历史维护记录保留当时使用该脚本的事实，不回写历史。
