## 后续修订（2026-09-03 同日）

### 1. `class="pb"` 的来源澄清

`class="pb"` **不存在于 BW 原始 EPUB**（源文件内 `pb` 命中 0 次），完全由本仓库工具链注入：

- `merge_bw_pages.add_class_pb()` 在 `merge_unit()` 中给合并边界打标；
- `bw_preprocess.inject_pb_css()` 往书内 CSS 追加 `.pb { page-break-before / break-before }`。

即 BW 的"分页"本来是**物理文件边界**，合并成章节文件后边界消失，改由 `class="pb"` 承载，而该属性**不占物理行**。

### 2. D 类（中文侧行数更多）的真实成因＝中文旧合页写法

中文缓存早期用「该页最后一段之后紧跟 1~2 个独占 `<br/>`」表达同一分页边界，现已被日文侧 `class="pb"` 取代，这些 `<br/>` 成为纯多余物理行——这才是 D 类行数差的根因，不是"中文段落未合并"。

据此新增 `tools/fix_legacy_pagebreak_br.py`：中日正文行 1:1 走查，在每个 `class="pb"` 边界上**比较两侧 `<br/>` 连段数量**，只删中文侧多出的部分；数量一致者为真场景分隔，一律保留。安全闸：日文侧更长、或遗留数超过该文件总行数差（说明别处缺行、属位置错配）时整体不删，交人工。

### 8. `bw_preprocess.py` 的 `--merged` 契约（工具缺陷修复）

### 10. 规则集 v6：单段排版 div 容器折叠推广

**证据先行**：只统计「行数不等」配对里日文侧多出的**严格单段**容器（3 行形如 `<div class="X">` / `<p>…</p>` / `</div>`），得到白名单 7 个类共 41 个容器：`align-center`(20)、`font-1em30 start-2em`(12)、`align-right`(3)、`gfont`(2)、`h-indent-5em`(2)、`h-indent-1em`(1)、`start-4em`(1)。普查同时给出两个必须回避的事实：

- 全缓存另有 ~398 个单段容器位于**奥付/版权包装页**（`copyright`、`release-date`、`author mfont`、`label`、`book-title-main mfont`、`start-3em`、`font-0em80` 等），按「原样快照」不得改动 → 用**证据驱动的显式白名单**而非类名族通配；
- 另有 **414 个容器内含 2 段以上**，折叠会把两段并成一行（违反行原子性）→ 必须排除。

**踩到的顺序坑（真实回归，已修）**：规则最初放在原 `align-end` 的位置（图片 br 清理之后）。此时折叠让 `<br/>` 与图片段**新暴露为邻接**，但「图片前/后填充br清理」已在前面跑过 → 第一遍留下 3 个 `<br/>`，第二遍才删，`S1_14-02` 等 4 个文件幂等性失败。把折叠规则前移到「页尾填充br删除」与「图片前填充br清理」之间后，幂等失败 **4 → 0**。

### 17. 校验方法上的三次假警报（教训）

本轮自建的验证脚本三次给出错误结论，均在落地前被自己纠正：

### 17. 中文侧图片行包 `<p>`（新增 `wrap_cn_image_lines.py`）

按「正文区以顶层块为行对齐原子」「正文中的图片正常占正文行」，把中文侧独占一行的裸 `<img/>` 转为 `<p><img …/></p>`。工具只解开**图片专用** div 容器（连续区段内容仅为 `<img/>` 与配平的 `<div>`/`</div>`），class 合并到 `<p>` 上以保留居中语义；含正文文字的容器、`<svg>` 内的 `<image>`、已在 L3 的篇首插图、`nav.xhtml` 一律不碰。

写盘前自我修掉两个缺陷：① 令牌按出现顺序处理（先弹栈会让闭标签行上的末图丢掉 `center`）；② 最初"删除任何只剩结构标签的行"过宽，会吃掉其它 div 的行，改为仅在图片容器配平时解包，并在配对表头（日文侧有同名文件）一律禁止删行；每文件写盘前做 `ET.fromstring` 校验。

结果：34 个文件、69 行图片转为 `<p>`；除 1 个无日文对应的包装页（`S1_03-Illustrations.xhtml` 14→12）外**行数全部不变**；图片 `src` 序列与可见文本逐字不变；裸 `<img/>` 残留 0。
