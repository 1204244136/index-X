# 全库中日语义逐行对齐治理体系与分阶段推进指南（2026-09-24）

## 背景与问题定义

仓库在 2026-09-03 完成了全库统一固定行模板（L1~L6）迁移与排版标签清理，`check_alignment.py` 达到 1105 个正文文件 0 结构问题的形式对齐。然而，**形式上的行数相等不代表实质上的语义逐行对齐**：

1. **历史翻译重组**：部分早期作品（如外典 S5 系列）民间译本存在局部句子合并、意译扩写补偿或倒装，导致中文与日文出现局部的“段落滑动错位（Semantic Drift Window）”。在错位区间内，物理行号虽然对等，但每行日文实际对应上一行或下一行的中文，严重影响读者双语对照与 BetweenLines 等下游 AI 校对工具的提取精度。
2. **启发式规则局限**：原 `diff_paired_lines.py` 依赖 Jaccard 字符重合度与行长比较，对纯假名日文句（如「わかった」）和正常音译产生大量误报（假阳性率曾高达 70%+），且无法定量测算错位区间的具体位移步长。
3. **超长周期风险**：全库共有 761 个配对单元、253,472 行正文文本（双侧逾 50 万行）。若不合理切分流程，全量矢量化推理与人工比对将耗费数小时并产生不可控的大规模 diff，陷入超长周期的任务风险。

---

## 解决方案：两级漏斗诊断体系与环境适配

基于 `C:\Users\12042\Documents\GitHub\BetweenLines` 的文本矢量化工具（`SentenceTransformer` 多语言模型 `paraphrase-multilingual-MiniLM-L12-v2` + ROCm/CUDA GPU 加速），设计并实现了 `tools/check_semantic_alignment.py`：

```
全库 761 单元 (25.3万行)
         │
         ▼
[Level 1: 极速启发式初筛] (纯CPU, 3秒完成)
         │
         ├─► 391 单元 (51.4%) 0 漂移绝对绿区 ──► [直接通过，无需重检]
         │
         └─► 370 单元候选疑点
                   │
                   ▼
[Level 2: 矢量化滑动窗口精检] (GPU批量加速, 自动调度 BetweenLines venv)
         │
         ├─► 消除意译/假名假阳性 (实测消除率 > 70%)
         ├─► 精准捕获结构性滑动错位窗口 (Drift Windows, 给出步长与置信度)
         └─► 输出全景健康评分与分级排查清单 (Summary & Windows TSV)
```

### 环境自适应设计
脚本在入口处集成 `ensure_vector_environment`：当检测到当前 Python 缺少 `torch` / `sentence-transformers` 时，自动探测并无缝委托给 BetweenLines 虚拟环境执行，向后兼容纯 CPU 启发式降级，维护者无需手动切换环境。
