# 智能体资料访问与受阻说明

文档职责与入口见 [文档索引](../README.md)。原文核对、外部证据／材料缺失或工具环境受阻时读取本流程；命令参数与退出码查 [工具合同](../../tools/README.md)，证据效力查 [翻译规范](../translation-spec.md#六证据边界判定时不得越界)。

## 交互职责

除阅读成品外，项目请求由对话智能体承接。智能体定位材料、选择并调用工具、处理可恢复的障碍，再向使用者说明结果。工具负责返回事实和诊断，skill 负责具体任务流程；缺输入说明由接收请求的智能体完成，不把命令行报错和整套维护环境配置交给普通使用者自行解释。

“原文真的是这样吗”属于只读核对。先查证据，不自动修改归档、发布、更新同步基线或创建提交；批量复核、术语替换与新书制作按实际授权转到对应 skill。

## 资料定位与恢复

1. **确定核对对象与证据要求。** 从书名、引句和现有内容定位完整作品号、表头及上下文；沿用可确认的上下文，不把内部编号问题推给使用者。文本含义通常可查工作源，注音、傍点、原始码位和分页要回查 BW 原始提取包。身份或版本仍有多个合理候选时，只询问影响本次判断的差异。
2. **核对已有来源。** 先查本次提供的资料、已配置的外部源和对应缓存；正文分析优先读可靠缓存，缺缓存时读归档。检查对象是本次作品和内容单元，不因目录存在就认定材料齐备；不以某个工具的默认路径缺失推断所有来源都缺失，也不为一次查询扫描整台机器。外部规范与译名表按 [外部依赖与核验](../translation-spec.md#外部依赖与核验) 定位；角色说话习惯表已在仓库内，见 [说话习惯表](../translation-spec.md#说话习惯表)。
3. **恢复可生成的输入。** 有匹配的现成工作源就直接只读使用；只有完整 BW 包时，单点问题可直接查原始分页及上下文，需逐行工具时才按 [BW 源流程](../../.agents/skills/bw-source-import/SKILL.md) 生成该任务所需工作源。只读查询的生成限于归档、缓存和 OneDrive 之外的显式暂存目录，验证后作为只读输入，不执行正式入库／发布。只有工作站原有同步任务才按原同步流程拉取；先保护未发布内容和现有基线。相关软件缺失时，按任务授权与项目安装入口恢复，无法自行完成再说明具体环境障碍。
4. **核实实际证据覆盖。** 核对完整作品号、表头、内容范围和版本；同行工具另验行数及结构。配对失效时可回原始分页按内容定位，不猜偏移、不拿相邻卷代替。只完成局部核对就报告局部；工作源未保留某个标记不等于原版没有该标记。读取到可靠范围后，才能把“没有命中”解释为该范围内未发现目标内容。
5. **完成核对或说明尚缺的最小输入。** 可恢复的问题处理后继续原请求；来源确缺、身份不明、不可访问或工具仍无法执行时，保留能独立完成的工作，按下节说明。新书交稿、指定图片、制作信息和简介等用户材料不得编造；全部材料齐备前不生成成品。

## 区分障碍再解释

| 已确认的状态 | 智能体的处理 |
| --- | --- |
| 默认路径不存在，实际来源尚未查明 | 继续定位配置和现有资料，不能直接宣称“没有原文” |
| BW 包存在，工作源未生成 | 直接取证或生成必要工作源；这是可恢复的准备步骤 |
| 本次作品的源资料缺失或不可访问 | 说明无法核实的对象，只索取该作品的源包或足够核验的原始页及上下文；局部页不冒充完整工作源 |
| 材料存在但版本、配对或结构不可靠 | 尝试内容定位；说明实际可核范围和仍需确认的差异 |
| 工具运行时、模型或权限不可用 | 报告工具未执行及具体环境障碍，不把它说成原文缺失或检查通过 |
| 有可靠检索／核对范围，但目标未命中 | 说明查过的范围与结果，区分“未找到出处”和“确认原文没有” |

说明用使用者能理解的语言，至少包含：**正在核对的对象、实际检查或恢复过的来源、当前不能判断的部分，以及继续所需的最小材料或操作**。只展示有助于解决问题的技术细节，不原样粘贴堆栈、私人路径或要求使用者部署完整维护工作站。未执行与未覆盖不写成零问题，不用中文推测补出日文结论。

例如，已检查可用来源且确缺该卷资料时可说明：“当前环境没有这部作品的日文源，尚不能确认这句中文是否对应原文。需要这部作品的完整 BW 提取包；若只核这一处，提供对应原始页及前后文也可以。”若 BW 包已存在，就先处理它，不使用这段缺源说明代替实际工作。

## 按角色准备资料

以下是智能体为任务核定材料的参考表，不要求使用者在提问前自行执行清单。角色由本次工作决定，不因为用户提出原文问题就要求其接管维护工作站。

| 使用者的用途 | 额外内容要求 |
| --- | --- |
| 阅读成品 | 发布 EPUB 和阅读器即可 |
| 中文检索、单侧检查、本地打包 | 仓库已含成品，只准备所用工具的软件环境 |
| 核实某部作品的原文 | 只需要本次核对的证据；优先使用已有源，缺失时按上述流程索取对应资料 |

完整内容维护需要保全的上游资料如下；单项工作按需读取，不要求每条命令同时取得全套资料。版本、唯一来源和凭据以 [外部依赖与核验](../translation-spec.md#外部依赖与核验) 为准。

| 维护者保存的外部源资料 | 用途 |
| --- | --- |
| 完整 BW 原始提取包 | 生成日文工作源、核对源文本与包内保留的制作信息；XHTML、图片、CSS 和导航属于同一包，不另计一套“原版资源” |
| 项目译名表 | 术语审定、译名落地核验 |
| 原始《翻译与修嵌规范.docx》 | 核对外部规范与仓库规范的对应关系 |

新书交稿、指定图片素材、制作信息、简介及确认的作品身份按卷提供，完整验收见 [新书导入流程](../../.agents/skills/volume-import/SKILL.md)。日文工作源由 BW 包生成，模板书通常仓库已有，不重复列为独立外挂源资料。

软件运行时、模型和 BetweenLines 的实际校对档案／预设属于所用工具的运行条件，按 [工具合同](../../tools/README.md#克隆后的运行环境) 准备。外部分发目录仅发布任务需要，配置与初始化见工具合同 C1；接管现有工作时保留未发布改动、同步基线和未完成会话。工作源、缓存、打包成品及报告可提供快照方便使用，但生成物与尚未完成的工作状态应分别判断，不因“可重建”覆盖后者。

## 完成条件

原文核对已给出实际来源、核对范围和有据可查的结论；或已清楚说明仍未核实的对象、已尝试的恢复及继续所需的最小输入。单侧检查、部分覆盖、分级报告或工具成功退出均不替代原文证据。内容写入另走 [EPUB 内容维护流程](content-maintenance.md)。
