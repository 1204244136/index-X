# EPUB 内容维护流程

文档职责与入口见 [文档索引](../README.md)。本文件承载内容修改的执行步骤；写入、共享工作区与版本控制边界见 [AGENTS.md](../../AGENTS.md)。只读原文查询与材料受阻先按 [智能体资料访问流程](reference-access.md) 处理，不触发本文件的修改、同步或提交流程。

本流程只适用于 EPUB 内容修改。工具和文档改动按 [工具合同](../../tools/README.md) 中的门禁与测试验证，不执行内容同步。

先确认运行环境：已配置外部发布源与同步基线的维护工作站执行下列三副本流程；普通克隆环境按 [克隆后的运行环境](../../tools/README.md#克隆后的运行环境) 运行。普通克隆尚未配置外部源与同步基线时，可在 `EPUB/` 本地修改、检查并提交，结果中明确「未同步／未发布」及未完成的日文核验；有日文工作源时仍执行适用的双语门禁。接入发布工作站前按现有冲突流程合并。该分支不适用于已有未发布同步产物的工作站，也不能据此跳过已配置环境的同步。

1. **写前同步**：先确定本任务作品范围，用 `python tools/publish_auto.py --only-books "<side/书目录,...>" --dry-run` 核对计划，再以相同范围执行。单本可用 `--pattern "*S3_09*"`，须确认没有命中其他作品。同步冲突按 [AGENTS 的数据流与编辑边界](../../AGENTS.md#数据流与编辑边界) 逐书、逐文件分析，协作归属按其「共享工作区协调」执行。
2. **分析与写入**：分析优先读缓存；已确认的内容只写 `EPUB/`。新书导入可在显式暂存目录预处理，最终结果必须落到归档；成品生成按 [新书导入 skill](../../.agents/skills/volume-import/SKILL.md) 核对材料，先定位与恢复可生成输入，用户材料确缺时再集中索取，齐备前不生成成品。规范化、修复等写工具默认预览，明确 `--apply` 才写入；暂存模式与路径限制见工具合同。
3. **验证**：按修改类型运行对应门禁，检查 `git status`、变更文件数、`git diff --stat` 并抽查 diff。批量校对产出按 `.agents/skills/proofread-review/SKILL.md` 复核；术语收敛按 `.agents/skills/translation-term-unification/SKILL.md` 执行。
   - 任何改写行内文字的改动（重译、通校、回改、术语替换、标点调整）都可能重新划定加粗边界或挪动标点，写盘后必须重跑字符级规范化并确认 0 命中：`python tools/text_norm.py --dry-run`（可加 `--pattern "*S3_09*"` 限定书籍）。`<b>` 段内含标点同时是 `check_epub_health.py --strict` 与 `publish_auto.py` 发布预检的**阻断项**——留着不修会卡住写后同步，或由每日规范化 CI 代为提交、使「结论 ↔ 落地」分家。加粗口径见 `docs/translation-spec.md` 一.8。
   - 通校／重译这类整批改写同样算「动译名」：整批 `rewrite` 里的用词也要比对 `docs/translation-name-rulings.md`，不得只按日文字面直译；比对方法与案例见 `.agents/skills/proofread-review/SKILL.md` §二.5。写盘后另跑 `python tools/check_term_anchors.py --strict`，确认裁定表锚点没有被改回误形（0 命中才放行；该门禁已接入 `publish_preflight.py`）。
   - 同一批改动还要查**呼应一致性**：后文引述前文台词、叙述回指前文说法、同一句复现、角色口癖复现——任一被改动，其对应侧必须同步；只改一侧就是呼应断裂，而它**不被任何既有门禁覆盖**（行数、模板、XML、加粗、术语裁定全都通过）。写盘后用 `python tools/check_echo.py --book <作品号>` 取候选并逐条回日文原文判定；**整卷通校／重译后还必须核其中的「术语多译」类**，确认同一日文术语在卷内没有被译成多种写法——句子级候选为零不等于术语一致。改动达到近重译级的卷必须整卷核，不能只跑工具就算完。**中文两侧字形不同不等于必须统一**：同一句日文在随口与庄重等不同语气下用不同中文是允许的，判断依据是日语侧的语气层。候选只说明「应当一致」，**不说明往哪边一致**：涉及高频叙述定型（`息を吐く` 这类全库数十次以上的表达）时，取形方向须用 `python tools/check_echo.py --convention "<日文正则>" --convention-words "<中文正则表>"` 查全库惯例，卷内多数不是依据（S5_03_02 曾据此改出与全书相反的一处，见 `cbee10ca`）。判据、三类候选与三种出口见 `.agents/skills/proofread-review/SKILL.md` 二.9／二.10 与 R4，规则正文见 `docs/translation-spec.md` 四.8。
4. **写后同步**：立即以写前核定的作品范围再次运行 `python tools/publish_auto.py --only-books "<side/书目录,...>"`，把本次修改发布到 OneDrive，并更新缓存、清单与拉取状态。
5. **留档与提交**：一次内容修改落在两本及以上作品时，在 `docs/maintenance-records/` 记录范围、文件数、依据、统计、验证与必要样例；中日同一作品算一本。单本修改以提交承载，不另留档。留档忠实反映修改事实，候选取舍登记 `docs/translation-name-rulings.md`；明显错误订正与规范执行不算裁定。只暂存本任务文件，完成对应环境的验证与同步后直接提交，不 push。

拉取、A/B/C 单方向发布、初始设置与全量重建的命令合同见 [工具合同](../../tools/README.md) 的 C1（同步与发布）。
