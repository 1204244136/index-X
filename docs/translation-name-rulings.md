# 译名裁定总表

文档职责与入口见 [文档索引](README.md)。

> 本文件只收录**裁定**：同一日文锚点存在两个及以上**都能忠实对应原文**的中文写法、必须在其中作出选择时，选择结果是什么、否决或并行了哪些候选、哪些情形裁定为**不作统一**。
>
> 译名统一、校对复核、新书导入、读者反馈勘误在动任何译名之前，先查本表；命中即沿用，不得另立译法。

## 一、什么算裁定

判据一句话：**需要说明理由才能否定的候选 → 裁定；一眼可见是错的、或照条文即可处理的 → 纠错／规范执行。**

自检问句：把结论写成「**A 也说得通，但我们选 B**」——

- **A 根本站不住**（错字、漏译、与原文所指不符、违反既有规范）→ 纠错，**不入**裁定；
- **A 也成立**（只是不如 B 合适）→ 裁定，**入**本表。

### 1.1 入裁定

| 情形 | 例 |
| --- | --- |
| 同一锚点多个译法都成立，必须选一个 | `ムト=テーベ` 底比斯／忒拜；`レギオン` 恶灵军团／雷格恩 |
| **中文里有看似对等的现成说法，但经原文或领域核查必须否决** | `少管所`（中国少管所属刑事设施，日本少年院是依《少年法》的教育·矫正设施）／`急性`（`劇症`＝fulminant，含严重与失控义） |
| 角色口癖、自称、固定语尾的定形 | `やめてよね`→可别啦；`当方`→本人；`大体`→说起来 |
| 敬称、虚词、注音取用等写法取舍 | `シュプレンゲル嬢` 小姐／女士；`神の祝福` 神之／神的；注音 `Original`／`本体` |
| 术语分层 | `サイド`／`側`；`魔術`／`手品` |
| 裁定「不作统一／按语义分轨」 | `空中分解`；`暴発` |
| 裁定「保留差异／并存」 | X 版与译名表固有差异；`吊人`／`倒吊人` |

### 1.2 不入裁定（归[第十一节](#十一不算裁定的事项纠错与规范执行)）

| 情形 | 例 |
| --- | --- |
| 错字、异体字、拼写错 | `破环神`→破坏神；`涩谷PEIKO`→`涩谷PELKO` |
| 日文汉字／日文词残留 | `矶塩`→矶盐；`RSPK症候群`→RSPK综合征；`真夏`→盛夏 |
| 漏译补回 | 绢旗最爱 `超`；奥雷欧斯·伊萨德 `〜然` |
| 机械替换误伤 | `冰空调息`→冰冷气息 |
| 词义译错（查词典即定，非候选取舍） | `悪びれ`（原文作 `悪びれもせず`／`悪びれた様子もなく`）→毫无愧色 |
| 规范条文的执行 | 凭空注音禁令、当て字基文照读、连接符、全角＆、加粗标点、异形词规范词形、海峡用词、标题英文保留 |

纠错与规范执行**不需要**登记裁定（唯一答案或已有条文），由提交承载。

## 二、与其他文档的边界

职责登记见 [文档索引](README.md)。本表负责已经落地的候选取舍；规范、取舍原则、X 版固有差异与修改事实分别回其对应文件，不在本表另立规范。

## 三、效力与判定优先级

判定顺序固定为：

1. **本表（裁定）与译名表**（已决口径）
2. **日文锚点**（原文写法与注音）
3. **成品语料一致性**

> 维护记录与提交只用于追溯「本次改了什么」，**不列入本依据链**：留档忠实反映修改内容，翻译方案一律以本表为准。

**频次只能用于「发现冲突」，不能作为裁定依据。** 罕见专名在库内只出现一两次，「表内零用例」或「成品全库通行」都只反映本库，不代表通行度；人名／专名取舍按[译名选取规范](translation-name-selection-spec.md)，并查独立权威资料（**不使用魔禁维基／灰机 wiki 验证**——译名表即由该 wiki 提取，用它验证属循环论证）。

本表与提交中的结论冲突时，以本表登记的**最新落地结论**为准。

## 四、使用规则

1. 本表命中即沿用；确需改动已在表的裁定，必须说明前次结论哪里不适用（`SKILL.md` §S0）。
2. 已被推翻的旧方向**不单列**：凡「被否决或并存的候选」列注「曾…后回滚／推翻」的写法不得沿用。
3. 标「不作统一」「按语义分轨」的锚点，复核时**不得再当异译翻出**。
4. 「备注」列只写**一句话**能说明判定的理由；无此类理由的条目留空（留空不代表该条无需理由，只表示理由无法压缩成一句）。
5. 本表是译名类裁定的唯一汇总处：`.agents/skills/translation-term-unification/SKILL.md` §六 只留入口，不重复维护。

### 7.1 与灰机 Wiki 译名表的人为固有差异

X 版与灰机 Wiki 译名表之间**人为制定的固有差异**：取舍而非缺陷，两侧各自维持自身写法，不计入待改、不得按表回改；X 版成品一律按本节的「裁定」列取值。

**类别规则**：

- **符合语境**：台版按上下文选词，X 版统一为单一写法。
- **中文注音**：基文与表侧一致，只把 `<rt>` 注音由原文片假名改为汉译。
- **混乱统一**：同一注音（片假名）在表侧有多个汉字写法时，X 版统一为一个写法，并把注音改用拉丁字母。
- **原创词**：日文 neta 或外来语在 X 版另拟中文名（不音译、不照搬表侧）。
- **炼金术器具专名**：原文一律作「汉字类别名＋片假名专名」，X 版统一为**类别名汉译＋专名音译**。
- **泰勒玛与克劳利**：格言保留出版源的文白格言体与读音注记；`ハザード` 取「灾祸」义项，并兼顾事件与具体的物两种指代。

## 八、注音与体例

**`<rt>` 语种的判定轴**：注音语种按**读音层**的性质定，不按基文语种定（目的与形式的分层见[翻译规范](translation-spec.md) §三.1）：

| 读音层性质 | `<rt>` 写法 |
| --- | --- |
| 作品内专名（人名·能力名·组织名·装备名等，全库统一用拉丁原文的词条） | 拉丁：<ruby>一方通行<rt>Accelerator</rt></ruby>、<ruby>超电磁炮<rt>Railgun</rt></ruby> |
| 当て字义训、非专名外来语，且汉译与基文不同形 | 汉译：<ruby>三泽塾<rt>科学崇拜</rt></ruby>、<ruby>处刑塔<rt>伦敦塔</rt></ruby> |
| 北欧神话灵装／种族名 | 汉译，不保留拉丁（见下表） |
| 基文与读音同义（熟字训式） | 不标（`麦酒<rt>ビール</rt>` 不写成 ruby） |
| 原文带特殊注音、读音的汉译又与基文同形而无法分层 | 保留读音的拉丁原文：<ruby>時間割り<rt>カリキュラム</rt></ruby> → <ruby>课程<rt>Curriculum</rt></ruby> |

判定顺序：先看读音层是否作品内专名，再看汉译是否与基文同形，两者都不成立才考虑不标。原文通篇裸写时不得补注音；原文带特殊注音时译文必须保留对应注音，末行只在这一义务成立、且汉译无法与基文分层时适用。

## 十二、本文件的维护

1. **只收裁定**：候选都成立、需要选择时才登记；纠错与规范执行不进本表（见第十一节）。
2. **新裁定落盘即更新本表，且必须经维护者确认**：任何译名统一／复核任务产生新裁定时，在本表补一行（日文锚点、裁定、被否决或并存的候选、备注、判定）。**agent 只能提出候选与依据，不得自行写入本表**。
3. **分工**：翻译方案（裁定）写进本表；`docs/maintenance-records/` 只忠实反映本次修改内容（范围、文件数、统计、验证、样例），不重复登记方案，也不作为方案依据。
4. **不重复维护**：`.agents/skills/translation-term-unification/SKILL.md` §六 只保留指向本文件的入口。
5. **裁定被推翻时不新开一节**：最终结论留在本行，「被否决或并存的候选」列**只列被否决的写法**，不写落地时间、次数与回滚经过——旧写法必须列出，否则后人会重犯。
6. **与成品同批提交**：裁定条目的登记**不单独开提交**，与触发该裁定的 `EPUB/` 成品改动**同批提交**，使「结论 ↔ 落地」一一对应、便于 `git show` 复核。只有新建本表、或对全表做整体整理（判据重订、结构重排）时才允许单独提交。
7. **§6.2 的角色列须回原文确认**：登记「角色」列前，必须读该句在 `.cache/epub-work/japanese-text/` 中的上下文确认说话人。复用差异清单、提案等工具产物只给译文与文件行号时，先补做说话人核对；**不得凭译文内容推测角色**，确实无法确认时留空并注明依据（如「（`S5_01_02`，英国清教相关人员）」）。角色认错会让「同一角色的同一句日文须逐字相同」这条判据失去适用范围。
8. **「判定」列的取值**：
   - 留空 = 「裁定」列写法必须落地（`／` 分隔时任一出现即算落地）；
   - `人读` = 条件式、分层、描述性或聚合条目，工具跳过判定并在报告中单列；
   - **匹配轴**（决定日文侧凭什么认定该锚点出现）：`匹配基文` = 只比基文，注音不参与（留空时的默认）；`严格全文` = 日文须写出 `<ruby>基文<rt>注文</rt></ruby>`，**裸写基文不在本行范围**（既不判落地也不报未落地）；`匹配注文` = 只认注文，基文可以是别的字（同一读音的当て字变体）。同一锚点的多行须声明同一轴，混用退回默认并由 `--audit-rulings` 报出。
9. **格式约定（工具解析依赖）**：锚点列用反引号包裹，一行的多个反引号内容都算锚点；**含注音的锚点不加反引号，直接写成 `<ruby>基文<rt>注文</rt></ruby>`**——反引号会让预览把标记当代码原样显示、注音不渲染，解析器把反引号内容与 `<ruby>…</ruby>` 一并算作锚点；**注音一律写成 `<ruby>基文<rt>注文</rt></ruby>`，不得写成 `基文（注文）`**——后者归一化后是另一个键，同锚点的多条登记会合不到一起；「裁定」列用 `／` 分隔多个可接受写法；中文括号注释不参与匹配；`<ruby>` 按基文与 `<rt>` 两层匹配；同一锚点的多条登记合并为候选集合（分层与同词异译按不同义项标识并列）；**不使用译名表的 `【】` 振假名范围标记**——`【】` 在译名表里标记注音范围、不属于名称本身，裁定表的锚点与写法一律不写它（解析时会剥掉，写了只会与表侧记号混淆）。
