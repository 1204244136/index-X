# 翻译规范（EPUB 成品层）

文档职责与入口见 [文档索引](README.md)。

本文件是 `EPUB/` 中文成品的**翻译与语言规范正文**：译文在标点、注音、译注、拟声语气词、译名一致性等方面应写成什么样，以及哪些差异**不算**缺陷。

规范按「落到 EPUB 最终正文」的口径写。只服务于交稿制作的机制（`|基文[注文]` 注音稿写法、内联 `（*译注：…）`、docx 交稿格式、漫画修嵌）在成品中已转换成 `<ruby>` / Note 脚注页 / 固定行模板，不在这里反向要求。

## 规范的来源与三处落地位置

| 位置 | 角色 | 谁改 |
| --- | --- | --- |
| 《翻译与修嵌规范.docx》（仓库外，译者/校对方持有） | 规范的来源与交稿层要求 | 翻译团队 |
| **本文件** | 成品层的规范正文汇总，供人工校对与 agent 判定时引用 | 本仓库维护者 |
| `tools/check_translation_spec.py` | 规范的机器检查实现（P1–P16，只读报告） | 本仓库维护者 |
| BetweenLines `src/workbenches/translation-compare/ai/profiles/novel.js`、`demo.js` | 同一规范在 AI 校对层的实现（提示词档案） | BetweenLines 维护者 |

表中《翻译与修嵌规范.docx》是规范的来源，其余三者是同一套规范的不同侧面：本文件写「应该是什么样」，检查工具写「怎么批量发现」，AI 档案写「怎么让模型按它判」。**改动成品规则时检查其他实现的对应项并记录同步状态**；本仓库的成品判定以本文件为准，交稿层要求回原始规范。外部原始规范与本文件有实质冲突时，先标明冲突并核实，不能假定已同步。

结构、命名、行模板、图片资源及物理换页等**版式规约**见 `AGENTS.md`；**译名在多个候选之间的取舍优先级**不在这里，见 [译名选取规范](translation-name-selection-spec.md)；检查工具的用法与参数见 `tools/README.md`。

## 一、标点与字形

1. **标点全角化**：中文正文里的标点一律用全角字形（`，。、？！：；（）「」『』《》`）；省略号用 `……`，破折号用 `——`；半角标点只允许出现在 ASCII 数字、英文缩写、URL 与代码里。整段英文句子反过来必须用半角。宽度或体例在同一书内明显不一致 → 缺陷。品牌名与其它正文英文中的连接符统一使用半角 `&`；在 XHTML/XML 源码中必须序列化为 `&amp;`，不得使用全角 `＆`，也不得写裸 `&`。
   - 机器检查：`P1`（半角逗号/分号/句号/问号/感叹号/冒号）、`P2`（半角波浪号 `~` 应为 `～`）。
2. **引号体例**：中文语境用直角引号 `「」`，不用弯引号 `“”‘’`；书名用 `《》`。
   - 机器检查：`P6`。
3. **间隔号**：用中文间隔号 `·`(U+00B7)，不要与日文点号 `・`(U+30FB) 混用；Note 页引用日文原文属合法例外。
   - 机器检查：`P7`（warning，报告附分册 `・`/`·` 分布表）。
   - **西文单字母缩写例外（外文缩写与中文并用时）**：**中文与外文缩写之间用间隔号 `·`，缩写字母之后用下脚点 `.`**（其后不再加间隔号）。例：`エニーリャ＝G＝アルゴヌスカヤ` → `艾妮莉亚·G.艾尔格斯卡娅`、`ブラッシャ＝P＝マールハイスク` → `布拉沙·P.马尔哈伊斯克`；全部由缩写组成的 `H・T・トリスメギストス` → `H.T.特利斯墨吉斯忒斯`。完整名字成分之间仍用 `·`（`ロバート＝ウィリアム＝フェルキン` → `罗伯特·威廉·费尔金`）；缝合类术式／灵装、三段及以上神名、复合姓氏仍用半角 `-`（既有例外，不变）。
     > **依据**：《图书编辑体例规范》三（二）——「外国人名的缩写字母与中文翻译并用时，缩写字母与中文之间用下脚点(.)标示；中文与外文之间用间隔号（·）标示」（示例：`埃德蒙·S.卡彭特`、`A.罗伯特·李`）；W3C《中文排版需求》(clreq) 5.1——「当外语人名缩写成一个字母时，其后宜使用西文句点，而非中文间隔号」。
     > **不作为依据**：中文维基百科条目名作「约翰·F·肯尼迪」（缩写字母后也用间隔号），属维基自身的条目命名习惯，与本项目规范相左。
4. **问叹顺序**：统一写成 `？！`（问号始终在感叹号左边），数量与原文一致；写成 `！？`、增减问号感叹号 → 缺陷。
   - 机器检查：`P3`。
5. **省略号**：规范写法是 `……`。
   - 写成连续句号或连续英文句点（`。。`、`。。。`、`...`、`......`）→ 缺陷（`P4`）。
   - 省略号后不保留句号/点号（`……。`、`……・`）→ 缺陷（`P5`）。
   - 单个 `…`（未与另一个 `…` 组成 `……`）：提示级，需确认是否有意为之（`P12`）。
   - 断断续续的表达用空格示意属规范做法，不是缺陷。
6. **数字与单位**：
   - 小数用阿拉伯数字（`0.7`），不得写成汉字数字 + 小数点（`〇.七`、`三·五`）→ 缺陷（`P14`）。
   - 数字编号类专有词（角色编号、机体编号等）在正文用阿拉伯数字、插图内可用汉字，两种写法并存不算不一致。
   - 单位优先与日文原文对应：`キロ` 译「千克」或「千米」，不写「公斤」「公里」（`P9`，warning）。
   - **例外（项目名分轨）**：路跑／街道赛事等**项目名**按中文体育定名惯例写「公里」（如 `一〇キロ走` → 「十公里长跑」），`P9` 只约束一般距离、时速等单位用法；此类项目名的译法属误译订正，见[译名裁定总表](translation-name-rulings.md) §11.1。`P9` 已按赛事类型词表自动放行项目名，**词表唯一来源是 `tools/check_translation_spec.py` 的 `P9_EVENT_SUFFIXES`**，本文件与 `tools/README.md` 只留指针、不复制词表。
7. **语气词与拟声词**：按中文语境选词，替换是规范要求而非误译。
   - `チッ` → 「啧」而不是「切」；`まあ` 不译「嘛」；`やれやれ` 不译「呀嘞呀嘞」；`あら` 不译「啊啦」（`P11`，info 级示例词）。
   - **招呼语不音译**：`やっほー`／`やほー` 一类招呼语（含 `やっほい`、`やっほーい`、`やっほっほー`、`やっほーう`、`いやっほう`、`やふー` 等变体）按中文语境译成「嗨」「你好」等中文招呼语，可酌情带波浪号（`～`）；**不得音译**成「呀吼」「呀呵」「呀呼」「呀嗬」，也不得写成拉丁化的 `YAHOO`／`Yahoo`。同源的欢呼 `ひゃっほー` 按语境译「好耶」等中文感叹，同样不音译（`P11`，info 级示例词）。
   - **否定、答错的拟声不音译**：`ぶっぶー`／`ブッブー`（含 `ぶぶー`、`ぶっぶっぶー`）表示「不对、答错了」时按中文语境译「错了」「错啦」等；不得音译成「吥吥」「噗噗」「哔哔」，也不得写成拉丁化的 `bubu`（`P11`，info 级示例词）。
     - 语境边界：本条只约束**人物台词**中表示否定、答错的用法。**非人声的纯音效（游戏机失败音、汽车喇叭与引擎声等）保持既有写法、不按本条改动**——它们不是台词，音译或意译都维持原样。表不满嘟囔的 `ぶーぶー`（如 `ぶーぶー文句を言う`）译「嘟嘟囔囔」，不套用「错了」；作品专名里的 `ぶーぶー`（如后记提到的 `ぶーぶーのアビス`）不适用本条。
   - 不出现儿化音。
   - 拟声词后的 `と` 不译；表推测语气的 `？` 在成品中加括号（`？`）；话被打断处用拉丁字母代替尾音；异口同声写成 `「「…」」`；小声嘀咕不加引号；说话开头音的停顿重复改用顿号。
8. **内联强调与分层**：原文右侧傍点（着重号）在成品里表现为**加粗**；加粗是排版转换结果，不是语气强调的增译。原文傍点对应的文字没有加粗、加粗落在标点上、加粗范围与傍点明显不符 → 缺陷。
9. **规范汉字与异形词**：以教育部、国家语委《第一批异形词整理表》及《现代汉语词典》（第7版）推荐词形为准，中文正文统一使用规范推荐词形，淘汰非推荐异形词。防止因港台繁体底稿转换不彻底或输入习惯差异造成同书或跨卷词形混用。
   - 典型词形：统一写作「想象」，淘汰「想像」（注意甄别「想·像这样」「想·像……一样」等动词＋介词/比喻的合法句法组合，不作机械替换）；统一写作「身份」，淘汰「身分」；统一写作「角色」，淘汰「脚色」。
   - 机器检查：`P15`（warning）。

## 二、成对标记与句末点号

1. **引号用途**：
   - 背景音与非人声（电话、广播、档案、回忆）或说话人看不清时用 `『』`，正常对话用 `「」`。
   - 纯拟声词构成的发声/音效（「嘎吧！」「砰！」）允许用 `「」`，不得判为误用或强改 `『』`。
   - 嵌套按层交替：外层 `「」`、内层 `『』`；最外层本已是非人声 `『』` 时内层回到 `「」`。`『』` 只在最外层表示非人声，被另一对引号包住时只是内层引用。
   - 层级或用途错误、误把背景音写成普通对话造成说话人混淆、嵌套顺序相反 → 缺陷。
   - **证据边界**：成品用 `「」`/`『』` 标记被提及的词、短语、心声、拟声或招牌是常规写法，而日文原文在这些位置常常不加引号。**仅凭原文没有引号，不得判定成品「误加引号」**，也不得据此增删引号。
2. **成对标记内侧的句末点号**按中文规范定位置，不以日文原文的标点为准：
   - 标记内是完整引述的一句话，或整行就是一段括注（如 `（……这样。）`）时，句末点号（`。？！……`）落在标记**内侧**；成品漏掉内侧点号、或把点号挪到外侧 → 缺陷。
   - 标记内只是半句话、一个词、短语或拟声（被提及而不成句）时，点号落在标记外侧是常规写法，不构成缺陷。
   - 日文原文常在 `」`、`）` 前省略句末点号，成品在内侧多出的这个点号**不是增译或瑕疵**，不得据此判缺陷或删掉它。
   - 句末点号与句内点号之间的取舍（如把 `。` 改成 `，`）属译者断句习惯，不单独构成缺陷。
3. **行末点号不逐行比对日文（裁定：不敏感）**：中日两侧行数一一对应，但**每行的行末点号按中文断句习惯写，不要求与日文同行一致**。中文行末作 `，` 而日文同行作 `。`（或反之）属译者断句习惯，**不构成缺陷**——机器检查与人工复核都不据此判缺陷，也不得为「与原文标点对齐」而改动行末点号。全库此类行有数百处（如 `S3_06-03` L14 中文行末作 `，`、日文同行作 `。`），属常态而非个例。

## 三、注音、译注与换页（成品表现）

1. **注音**：稿件写作 `|基文[注文]`，成品写作 `<ruby>基文<rt>注文</rt></ruby>`。
   - 只有需要保留读音的术语与义训才在成品加注音；普通词、生僻字读音和单纯外来语不需要。
   - 该注音的术语没有注音、不该注音的义训或外来语却注了音 → 缺陷；普通词没有注音不算缺陷。
   - `注文` 里的日文假名应译为汉语（`P10`）；空 `<rt>`、`<ruby>` 缺 `<rt>` 属提示项。
   - **不得凭空创建注音**：**原文该词没有读音（日文原版从未给它注音），译文就不得自行加 `<ruby>`**。日文原版对术语通常只在首次出现处注音、后文裸写，这种「原文注过音、译文在后文补注音」属允许的术语标注；但原文通篇都是裸写（如 `グンタイアリ`、`シスターさん`、`メタルイーターＭＸ`）时，中文侧写 `<ruby>职业讨债人<rt>行军蚁</rt></ruby>`、`<ruby>Sister<rt>修女</rt></ruby>`、`<ruby>钢铁破坏者<rt>Metal Eater</rt></ruby>` 即为缺陷。判定以**术语**为单位核「原文是否注过音」，不以单行为单位。
   - **注音的取用按「目的」与「形式」分层**（下例 ✔️ 为规范写法、❌ 为缺陷写法）：
     - 按目的分：① 双重含义（基文与读音各表一义），通常汉译；② 表「中二」，通常拉丁化。
     - 按形式分：
       1. **以专名为主的读写相异**（咒语、能力名、魔法名、物品名等）→ **拉丁化**：
          - `<ruby>超電磁砲<rt>レールガン</rt></ruby>` → `<ruby>超电磁炮<rt>Railgun</rt></ruby>` ✔️
          - `<ruby>四獣ニ命ヲ<rt>はたらけバカども</rt></ruby>。<ruby>北ノ黒式<rt>げんぶ</rt></ruby>、<ruby>西ノ白式<rt>びやつこ</rt></ruby>、<ruby>南ノ赤式<rt>すざく</rt></ruby>、<ruby>東ノ青式<rt>せいりゆう</rt></ruby>` → `<ruby>号令四兽<rt>你们这些家伙动作快</rt></ruby>。<ruby>北之黑式<rt>玄武</rt></ruby>、<ruby>西之白式<rt>白虎</rt></ruby>、<ruby>南之赤式<rt>朱雀</rt></ruby>、<ruby>东之青式<rt>青龙</rt></ruby>` ✔️
          - `<ruby>世界を構築する五大元素の一つ<rt>MTWOTFFTO</rt></ruby>、<ruby>偉大なる始まりの炎よ<rt>IIGOIIOF</rt></ruby>` → `<ruby>构筑世界五大元素之一<rt>MTWOTFFTO</rt></ruby>、<ruby>伟大的始祖之炎啊<rt>IIGOIIOF</rt></ruby>` ✔️
          - `<ruby>灰は灰に<rt>Ash To Ash</rt></ruby>、<ruby>塵は塵に<rt>Dust To Dust</rt></ruby>、<ruby>吸血殺しの紅十字<rt>Squeamish Bloody Rood</rt></ruby>！` → `<ruby>尘归尘<rt>Ash To Ash</rt></ruby>，<ruby>土归土<rt>Dust To Dust</rt></ruby>，<ruby>吸血猎杀十字<rt>Squeamish Bloody Rood</rt></ruby>！` ✔️
       2. **以非片假名转写的外来语为主的读写相异**，同时表达相近甚至相反等多重意思 → **汉译**：
          - `<ruby>木原数多<rt>けんきゅうしゃ</rt></ruby>` → `<ruby>木原数多<rt>研究者</rt></ruby>` ✔️（形式示意；BW 源中该词只注 `きはらあまた`）
          - `<ruby>最強<rt>さいじやく</rt></ruby>VS<ruby>最弱<rt>さいきよう</rt></ruby>` → `<ruby>最强<rt>最弱</rt></ruby>VS<ruby>最弱<rt>最强</rt></ruby>` ✔️
          - `<ruby>三沢塾<rt>かがくすうはい</rt></ruby>` → `<ruby>三泽塾<rt>科学崇拜</rt></ruby>` ✔️（形式示意；BW 源中该词只注 `ほんだい`／`ここ`）
          - `<ruby>処刑塔<rt>ロンドンとう</rt></ruby>` → `<ruby>处刑塔<rt>伦敦塔</rt></ruby>` ✔️
          - 有时会出现符合本条、但恰好是外来语而**难以判断**属第 1 条还是第 2 条的情况，建议与管理员讨论后定，如：`<ruby>向き<rt>ベクトル</rt></ruby>` → `<ruby>方向<rt>矢量</rt></ruby>` ✔️
       3. **日语中常见的「把外来语配上含义完全相等的汉译」（类似熟字训）**，多见于非专有名词 → **不标**：
          - `<ruby>麦酒<rt>ビール</rt></ruby>` → `<ruby>啤酒<rt>Beer</rt></ruby>` ❌；`啤酒` ✔️
          - `<ruby>煙草<rt>タバコ</rt></ruby>` → `<ruby>烟草<rt>Tabacco</rt></ruby>` ❌；`烟草` ✔️
       4. **仅以外来语出现的名词** → **不标**：
          - `ロジスティクスホーネット` → `<ruby>物流黄蜂<rt>Logistic Hornet</rt></ruby>` ❌；`物流黄蜂` ✔️
          - `アンチスキル＝アグレッサー` → `<ruby>警备员·假想敌<rt>Anti-Skill·Aggressor</rt></ruby>` ❌；`警备员·假想敌` ✔️
          - `ハイボルテージ＝カッティング法` → `<ruby>高压切割法<rt>High Voltage Cutting</rt></ruby>` ❌；`高压切割法` ✔️
          - `オーバーハンティング` → `<ruby>超量猎捕<rt>Overhunting</rt></ruby>` ❌；`超量猎捕` ✔️
   - **假名注音的拉丁保留只限作品内专名**：人名·能力名·组织名·装备名等在全库统一用拉丁原文的词条，其注音写成拉丁形（`アクセラレータ`→`Accelerator`、`アンチスキル`→`Anti-Skill`、`シスターズ`→`Sisters`、`レベル５`→`Level 5`）。描述性外来语**普通词**不属于这一类，即便原文是片假名也要译为汉语（`グロテスク`→怪诞、`オカルト`→超自然、`チカラ`→力量、`ルール`→法则），不得为"洋味"保留拉丁。具体取值查当前译名表与裁定；历史语料计数不替代本条判定。
   - **判定「原文是否带注音」必须回 BookWalker 分页源核对**，不能只看 `.cache/` 的日文缓存：缓存区的日文 XHTML 是 `bw_preprocess.py` 的预处理产物，只保留特殊注音（当て字/外来语），普通读音已被合并丢弃。原文里普通词的假名读音**不是**给成品补注音的理由，也不因成品未保留它而算缺陷。
2. **译注**：稿件写作 `（*译注：…）` 跟在被注文本之后，成品表现为 EPUB 注释标记 `<a epub:type="noteref"><sup>㊟</sup></a>` 与对应 `-Note.xhtml` 条目页。译注条目的顺序由正文首次引用顺序决定，用 `tools/check_note_order.py` 检查、`tools/reorder_notes.py` 重排。
3. **分页与空行**：成品版式的换页标记、源结构恢复和行模板以 `AGENTS.md`「Agent 操作边界」为准；图片与标题分层属于结构，不参与逐字语义判断。

4. **方向敏感符号**：通信标识、箭头与方向标记会随版式方向改变朝向——日文竖排里的 `∨`/`∧` 在中文横排通信标识中可分别写成 `＞`/`＜`（如「发话者∨接收者」转为「发话者＞接收者」）。只要符号的通信、分隔或指向功能与位置、数量一致，**这种方向变化不算缺陷**，不得判为擅改、漏译或误译；同形符号若功能本身不同，仍按语义判断。

## 四、语义与信息

1. **语序、句式与断句不同不算缺陷**：原文是分页源整理后的对齐工作源，成品经校对、修嵌与构建统一了标点、引号、注音、加粗与空行，二者不是逐字对应。译者可以打碎语序、拆分长句、改变描述方式以符合中文说话习惯；人物、事实、数字、否定、时态、因果与语气一致时不判缺陷。
2. **日式句法照搬进中文 → 缺陷**：谓语先行的倒装与句末追补主语、句末突兀吊挂代词、把日文省略或后置的主语与敬体称呼按字面直译。这一条同时约束改写本身——语序可以重排，但不得保留或引入日式倒装与句末吊挂的代词。
3. **必须判缺陷的语义问题**：遗漏原文信息、加入原文没有的事实、把否定/时态/因果/行为主体弄错；照搬日文导致中文成分残缺或指代不明（可按中文习惯补上原文与上下文已确立的主语，但不得新增原文没有的行为主体）。
4. **连接词独立成段**（如单独一行的 `そして、`）时，成品按规范用破折号或逗号衔接（如「随后——」）；连接词另起、句读改变都不算缺陷，但没衔接导致该行读不通、或句末缺标点 → 缺陷。
5. **重复出现的字或符号**：数量与原文一致或相近即可；用汉字或破折号代替长串假名属规范做法。
6. **原文晦涩、比喻跳脱或刻意重复属于原作风格**：能合理解释语义时，不要因读起来不直白而判缺陷，也不要把晦涩当成信息缺失。
7. **咒语、咏唱与仪式台词**允许为了美感和中文语感调整句式（例如把命令式短句处理成更完整的祈使句）；只要术式含义与指向对象不变，不得按逐字直译判为增译或改写。

## 五、译名与专有写法

1. **系列名写作「某魔法的禁书目录」。**
2. 系列名、专有名词与术语以本项目译名表为准；**台版、网翻或维基旧译名不要回改**；某一译名在多个候选之间如何取舍以 [译名选取规范](translation-name-selection-spec.md)（从俗 → 从官 → 自拟）为准；本项目与灰机 Wiki 译名表的人为固有差异参见 [X 版译名差异说明](x-translation-differences.md)；同一术语在同一卷内保持一致比单行措辞更重要。
3. 术语统一以**日文写法为锚**，不做无锚点的全局替换。已裁定的锚点与结论见 [译名裁定总表](translation-name-rulings.md)（如「サイド」→科学阵营/魔法阵营 与指示代词「側」→侧/那边的分层口径、超能力者排名「第X位」、「妹達（シスターズ）」单复数等）。
4. **刻意书写特征不是错字**：角色口癖、固定语尾与人物专属书写方式以译名表/说话习惯表为准；部分假名改写、穿插符号与「符号 + ruby 注音」的风格化写法（如安娜·金斯福德口吻的 `<ruby>〼<rt>是</rt></ruby>`）是刻意特征，不得判为错别字、病句或翻译腔，术语判定默认跳过这类行。
   - **繁简混杂不在 X 版保留之列**：汉化组把金斯福德说的话写成繁简混杂，用于对照日文的片假名／平假名夹杂；**X 版移除该改动，一律用简体**。X 版成品正文（含符号体台词）出现繁体字按字形缺陷处理，只有日文原文引用与制作人员署名可以保留原字形；`著`／`祇`／`潟`／`瞭` 一类简繁同形或中文规范本就用该字形的写法不属缺陷。裁定见[译名裁定总表](translation-name-rulings.md) §九。
5. 判定译名差异时注意 2 字词（「時代」「科学」这类）在正文里常以普通词义出现，只有达到门槛的长别名才能作为「译名不一致」的强证据。
6. **标题原本是英文的不能改**：章节标题（`<h1>`、`<h2>` 及其分层 `span`）以及导航元数据（`nav.xhtml`、`toc.ncx`）中，**原本是英文（外文题名／英文编码层）的绝对禁止汉化**，必须原样保留外文原文（例如章节外文题名 `BIFROST.` 必须保留英文，严禁改为「比弗罗斯特」）。术语与译名统一主要作用于正文文本；若章名原本即为中文且含异译术语，允许收敛中文用字（如「超绝者姆特·忒拜」统一为「超绝者姆特·底比斯」），但严禁将标题中原有的英文改写为中文。
7. **外国人名与外文专名防日语中转直译**：对于非日文文化背景的外国人名、外国地名及外语专名，必须遵循 [译名选取规范](translation-name-selection-spec.md)「外国人名/专名的原语还原原则（防日语中转）」——先结合角色国籍与文化背景反推其对应国语言（如英语、俄语、德语、法语、希腊语、希伯来语等）的原文拼写，再依据源语言权威译音标准直接译为中文，严禁直接按日语片假名发音进行二次音译转写（杜绝日式开音节化、鼻音增减或习惯性日式假名汉化用字残留）。

## 六、证据边界（判定时不得越界）

1. 日文对齐工作源经过录入与预处理整理，**注音、傍点、分页、引号与标点等信息可能缺失**：不得仅凭原文看不到某标记就判成品「多出该写法」是缺陷，反之亦然。只按原文中实际可见的内容判断。
2. 行边界由上游对齐决定，片段按片段范围判断：不补全成完整句、不改写上下句；对齐片段行（以续接标点结尾等）的行边界问题不属于翻译缺陷。承接重复开头（短行是下一行开头的先现）需结合下一行判断，不得孤立判为独立句。
3. 规范未覆盖且无法由原文证明的表达差异**不作为缺陷**；拿不准时转人工确认，不猜。
4. 原文是准入边界：成品中原文没有的特典、后记、译注、制作信息等内容不构成翻译缺陷，也不得为了让两侧一致而删除或改写它们。
5. **日文锚点用不妥协写法**：规范、裁定、留档、译名表和固有差异清单中的日文写法按标准小字假名、半角 ASCII 与半角 `=` 维护。BW 源可能为排印把小字假名改为大字、半角英数符号改为全角；这不决定词条的规范码位。检索时查询与源两侧同时折叠（全角 ASCII → 半角、小字假名 → 大字），逐字引证源字符串时才照抄源码位并注明源形。源自身可能混用码位，不能按单处源形回改译名表。原始码位与特殊读音回 BW 分页源核验。

「—」表示该现象不在 AI 档案里单列条目，并不表示允许：`P12`（单个 `…`）属提示级、需人工确认；`P15`（异形词）按「成品统一为规范推荐词形」处理。

## 八、维护口径

1. 本文件只写**规范条款**；具体词条的裁定结论写入 [译名裁定总表](translation-name-rulings.md)，修改范围与统计按 `AGENTS.md`「维护流程」的留档与提交项写入 `docs/maintenance-records/`（跨 EPUB 的修订留档），单本内部的订正由提交承载。
2. 规范变更检查机器检查器和 BetweenLines 对应项，更新 §七 对照表及必要的工具合同；仅有人工规则的事项标明未机械覆盖。每个外部实现的核验状态按下节记录，不能用对照表代替实际核验。
3. **作品专有数据不重复保存在本仓库**：译名对照表（本机文件）与说话习惯表（在 BetweenLines 当前 `profiles/demo.js` 中维护）由 BetweenLines 侧维护，本文件只引用，不另存副本，避免两处漂移。
4. 规范条款的新增或修订属于项目规约变更，需在提交信息中说明理由与影响范围。
